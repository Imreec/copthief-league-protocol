# pairing-artifacts — a full six-sub-game bundle in the played format

Fourteen artifacts for one synthetic counted series (`team-aleph` vs `team-bet`), generated by
[`../gen_pairing_artifacts.py`](../gen_pairing_artifacts.py) — regenerate any time; nothing is
hand-typed. The shapes mirror the [`PAIRING-PLAYBOOK`](../../docs/PAIRING-PLAYBOOK.md) campaign's
counted series (2026-08-04): same field set, same conventions, synthetic values.

Verify it with the kit's own gate — it passes, including uid **re-derivation** from the configs'
inline flat terms:

```bash
python tools/check_artifacts.py examples/pairing-artifacts
```

## What to look at, per file

| File | Worth noticing |
|---|---|
| `declaration_*.json` | The single home for **both teams'** hardware specs and identity; per-group `signature` is sign-then-insert over the block; headline `github_commit` per team + bare 40-hex form |
| `config_*_gNN.json` | The flat signed **14-key** terms inline — exactly what lets `check_artifacts.py` re-derive the `game_uid` instead of merely checking consistency (WARNINGS §2) |
| `log_*_gNN.json` | **Both conformant step-0 spellings in one file**: own records open with the slim `step_zero` (+ `declaration_ref`); `opponent_records` open with the reference's `system_spec` (hardware inline). A first move with a Hebrew hint + emoji, sealed with a real commit — if your serializer escapes non-ASCII, re-hashing THIS file is how you find out |
| `result_*.json` | The emailed binding report's full shape: per-sub-game `github_commit` maps (per role, changing between odd/even windows), audit verdicts, **armed league fields** (`games_played_including_this` bumped, `first_meeting`, diversity to the winner), and a `mutual_agreement.sha256` computed by the settlement consensus serialization (`vectors/report_consensus.json`) over the pairing-agreed trimmed scope |

## The consensus scope in this bundle

`mutual_agreement.sha256` here is hashed over `{game_id, aggregate, sub_games-trimmed-rows}` where
the trimmed row keeps `sub_game_number, roles, result, winner_group, tie, score` — i.e. everything
two honest teams must agree on and **nothing they may legitimately differ on** (timestamps,
envelope prose, key order). The serialization is the pinned spaced form; the **scope** is
pairing-agreed — agree it in Stage 4c of the playbook before your first compare, or your first
diff will read as a dispute.
